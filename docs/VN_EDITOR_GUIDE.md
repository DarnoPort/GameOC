# Visual Novel Studio — руководство пользователя

Статус: ранняя версия для ветки `feature/visual-novel-editor`. Описаны функции, присутствующие в коде этой ветки; полноценный графический QEMU-проход полного пользовательского сценария ещё проверяется.

## 1. Сборка и запуск

Нужны GCC с поддержкой 32-битного кода, GNU LD, NASM, Python 3 и QEMU.

Из корня репозитория:

```sh
make clean
make
make test
make run
```

`make run` создаёт `customos_data.img`, если такого образа ещё нет, и подключает его как IDE-диск QEMU. Существующий валидный образ не форматируется заново. Файл `customos_data.img` находится вне `build/`; `make clean` не удаляет его. **Не удаляйте образ, если хотите сохранить проекты и установленные новеллы.**

В стандартном лаунчере выберите **NovelStudio** стрелками и нажмите Enter.

## 2. Главное меню

- **Новый проект** — ввод имени, присвоение постоянного ID, создание исходного сценария и метаданных.
- **Открыть проект** — список сохранённых проектов из ProjectFS.
- **Продолжить** — открыть проект, который был активен последним.
- **Справка** — напоминание о горячих клавишах.
- **Выход в CustomOS** — возврат в лаунчер.

При создании проект получает демонстрационный сценарий на русском языке. Можно сразу запустить проверку, изменить его или стереть и написать свой.

## 3. Редактирование сценария

В редакторе используется одна текстовая область, поддерживающая UTF-8, русскую раскладку, вставку символов клавиатуры, удаление и навигацию. Подсказки в нижней части экрана показывают основные команды.

| Клавиша | Действие |
|---|---|
| Стрелки | Перемещение курсора |
| Home / End | Начало или конец текущей строки |
| PageUp / PageDown | Перемещение на страницу |
| Backspace / Delete | Удаление символа слева/справа |
| Enter | Новая строка |
| F2 | Сохранить проект |
| F3 | Проверить сценарий |
| F4 | Запустить тест без компиляции приложения |
| F5 | Собрать и зарегистрировать самостоятельную игру CBX |
| F12 | Переключить раскладку EN/RU |
| Esc | Вернуться в главное меню; несохранённые изменения требуют решения |

Исходник ограничен 48 КиБ. Одна реплика и подпись варианта меню ограничены 512 байтами UTF-8. В одной конструкции меню допускается до 16 вариантов. При превышении ограничений редактор или валидатор должны сообщить об ошибке.

## 4. Язык первой версии

Каждый сценарий должен содержать одну или несколько меток. Имена меток чувствительны к регистру. Допускаются ASCII-идентификаторы и корректные UTF-8-имена без пробелов; например `label начало:`.

Обычная реплика — любая строка в теле метки, которая не является командой и заканчивается точкой с запятой:

```text
label начало:
    Добро пожаловать в историю;
    return;
```

`jump имя;` немедленно переводит исполнение в начало указанной метки. Если метки нет, проверка завершится ошибкой. `return;` заканчивает всю новеллу. Возврат к месту перехода не реализован; команд `call` и `if` в первой версии нет.

### Меню выбора

У меню и каждой ветки есть отдельные маркеры завершения. Это сделано намеренно: парсер не определяет вложенность только по числу пробелов.

```text
label начало:
    Перед тобой две дороги;
    menu:
        Остаться дома:
            Сегодня будет спокойный день;
            return;
        endchoice;
        Отправиться в путь:
            Ты выходишь навстречу приключениям;
            jump лес;
        endchoice;
    endmenu;
    return;

label лес:
    Впереди шумит древний лес;
    return;
```

- `menu:` начинает выбор игрока.
- Заголовок варианта заканчивается двоеточием.
- Команды выбранной ветки идут после заголовка.
- `endchoice;` закрывает конкретную ветку.
- `endmenu;` закрывает меню.
- Если ветка не содержит `jump` или `return`, выполнение продолжается со следующей команды после `endmenu;`.
- Вложенные меню не поддерживаются.
- `return;` завершает всю историю. Если исполнение доходит до конца метки без перехода, оно также завершается.

Каждая исполняемая строка заканчивается `;`. Чтобы поместить буквальную точку с запятой в реплику, используйте `\\;`. Пустые строки и строки, начинающиеся с `#`, игнорируются. Неизвестные/неподдерживаемые директивы валидатор не выполняет; форму `@имя;` можно использовать для явной проверки неизвестной команды.

## 5. Проверка и тестовый запуск

Нажмите F3. Валидатор проверяет синтаксис, структуру меню, уникальность меток и существование всех целей `jump`. При ошибке выводится сообщение с номером строки.

F4 выполняет сценарий непосредственно в редакторе тем же движком, что используется в готовой новелле. Для текста нажмите любую клавишу. В меню используйте стрелки и Enter. Esc прерывает тест и возвращает в редактор. После небольшого изменения сценария повторная компиляция для теста не требуется.

## 6. Сборка самостоятельной новеллы

1. Сохраните сценарий клавишей F2.
2. Убедитесь, что F3 сообщает об успешной проверке.
3. Нажмите F5.
4. При успешной сборке редактор записывает отдельный файл `G_XXXXXXXX.CBX`, где ID постоянный и соответствует текущему проекту. Игра появляется в текущем лаунчере.
5. Выйдите в лаунчер, выберите созданную игру и запустите Enter.

Готовая игра — обычное приложение CBX с встроенным исходником истории и собственным проигрывателем. Для её запуска редактор не нужен. Исполнитель повторно проверяет упакованный сценарий при запуске.

## 7. Повторная сборка

Откройте прежний проект, измените сценарий, сохраните и нажмите F5 снова. Для одного ID используется тот же файл игры, поэтому повторная сборка не должна добавлять дубликаты.

ProjectFS при замене файла записывает данные в другой свободный слот, считывает их обратно для CRC-проверки и только затем переключает запись каталога. Если проверка сценария, упаковка или запись не удалась, предыдущий CBX не должен быть заменён неудачной сборкой. При недостатке свободного дискового слота новая запись завершается ошибкой.

После перезапуска CustomOS зарегистрированные CBX с именами `G_XXXXXXXX.CBX` перечитываются из ProjectFS в список приложений. Хранилище поддерживает 128 файлов и максимальный размер одного файла 64 КиБ.

## 8. Файлы проекта

ProjectFS использует плоские ASCII-имена:

- `P_XXXXXXXX.MET` — метаданные (версия формата, ID и название);
- `P_XXXXXXXX.SCR` — исходный сценарий UTF-8;
- `G_XXXXXXXX.CBX` — последняя успешно собранная игра;
- `LASTVN.DAT` — ID последнего открытого проекта.

Суффикс `XXXXXXXX` — восемь шестнадцатеричных цифр ID проекта. Исходный сценарий сохраняется отдельно и не уничтожается при компиляции.

## 9. Известные ограничения

- Редактор работает на низком разрешении 320×200 и четырёх оттенках серого.
- Файловое хранилище — простой фиксированный ProjectFS v1 поверх primary IDE-диска QEMU, а не полноценная POSIX-файловая система.
- ProjectFS хранит не более 128 файлов, максимум 64 КиБ на файл и имена только ASCII до 19 символов. Суммарная ёмкость слотов ограничена размером образа.
- Язык не поддерживает изображения, звук, переменные, условия, вызовы с возвратом или вложенные меню.
- Размер исполняемого CBX ограничен ProjectFS в 64 КиБ и ограничениями загрузчика приложений.
- CustomOS исполняет программы на уровне ядра; повреждённый CBX или ошибка в системном коде всё ещё способны нарушить работу всей ОС.

В эту документацию не включаются функции, которые пока только планируются.
