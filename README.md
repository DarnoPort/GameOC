# CustomOS: экспериментальная 2-битная операционная система

## Назначение

CustomOS — экспериментальная 32-битная x86-операционная система для запуска собственных приложений в формате CBX. В состав входят графическая подсистема 320×200 с четырьмя оттенками, клавиатура PS/2, таймер, API приложений, встроенный каталог AppFS и управление внешними приложениями.

## Архитектура

- **Платформа:** IA-32, Multiboot 1.
- **Язык ядра и приложений:** C с небольшими участками ASM в загрузочном коде и низкоуровневых частях ядра.
- **Сборка:** GCC с поддержкой 32-битного кода, GNU LD, NASM, Python 3 и QEMU.
- **Графика:** 320×200; упакованный внутренний буфер 2 bpp и четыре оттенка серого; вывод через VGA Mode 13h; растровый шрифт 8×8.
- **Ввод:** клавиатура PS/2, ASCII и UTF-8-кодовые точки, стрелки, Home/End, Delete, PageUp/PageDown, F1–F12; F12 переключает раскладку EN/RU.
- **Приложения:** CBX v1 по адресу 0x00400000; SDK API v4 предоставляет графику, UTF-8-текст, Unicode-ввод, таймер, постоянный ProjectFS и установку сохранённых CBX-игр.
- **Встроенные приложения:** AppFS, встраиваемый в ядро при сборке.
- **Внешние приложения:** отдельный AppFS-пакет, передаваемый загрузчиком Multiboot; при импорте CBX-файлы копируются в управляемую область RAM.

> **Ограничения безопасности:** приложения работают в том же адресном пространстве и уровне привилегий, что и ядро. Отдельный стек и очистка памяти после возврата пока не являются аппаратной изоляцией. Запускайте только приложения, которым доверяете.

## Встроенные приложения

1. **AppTest** — проверка загрузчика CBX и вызовов API.
2. **NovelStudio** — ранняя версия редактора текстовых визуальных новелл: проекты, UTF-8-сценарий, проверка, тестовый запуск и сборка самостоятельного CBX.
2. **SysInfo** — диагностическая информация.
3. **TextDemo** — демонстрация текстового рендерера и смены контраста.
4. **LogicCalc** — тесты арифметики и логики, интерактивный инспектор чисел.
5. **Dodge** — игра на выживание на основе мини-движка `apps/app_game/game_engine.c`.

## Как писать собственные приложения

### 1. На каком языке писать

Основной язык приложений — **C**. Каждое приложение должно экспортировать функцию входа с точной сигнатурой:

```c
int app_main(const customos_api_t *api)
```

Структура `customos_api_t` определена в `sdk/customos.h`. ОС передаёт указатель на неё в момент запуска. Через этот указатель приложение вызывает функции ядра.

На текущем этапе рекомендуется писать приложение на C и компилировать его GCC в 32-битный объект. Затем GNU LD связывает объект по скрипту `sdk/app.ld`, а `tools/cbxpack.py` превращает ELF в исполняемый файл CustomOS с расширением `.cbx`.

Это не обычная программа Linux или Windows: её нельзя запустить напрямую в терминале Ubuntu или двойным щелчком. Она использует API CustomOS и исполняется только внутри этой ОС.

### 2. Доступный SDK

Подключай заголовок:

```c
#include "customos.h"
```

Главные функции API:

| Группа | Вызовы | Назначение |
|---|---|---|
| Текстовый терминал | `api->print(str)`, `api->print_num(n)`, `api->print_hex(n)` | Вывод в текстовый VGA-терминал |
| Экран | `api->gfx_clear(color)`, `api->gfx_flip()` | Очистить графический буфер и показать кадр |
| Пиксели | `api->gfx_put_pixel(x, y, color)`, `api->gfx_get_pixel(x, y)` | Установка и чтение пикселя |
| Фигуры | `api->gfx_draw_line(...)`, `api->gfx_draw_rect(...)`, `api->gfx_fill_rect(...)` | Линии, контуры и заполненные прямоугольники |
| Круги | `api->gfx_draw_circle(...)`, `api->gfx_fill_circle(...)` | Контур круга и заполненный круг |
| Текст на экране | `api->gfx_draw_text(...)`, `api->gfx_draw_utf8(...)` | ASCII шрифт 8×8 и UTF-8 с кириллицей |
| Клавиатура | `api->kbd_has_key()`, `api->kbd_get_codepoint()`, `api->kbd_wait_codepoint()` | Очередь клавиш и Unicode-кодовые точки; `api->kbd_russian_layout()` возвращает состояние раскладки |
| Время | `api->timer_get_ticks()`, `api->timer_sleep(ms)` | Получить тики таймера и сделать паузу |
| Завершение | `return 0;` или `api->exit(code)` | Вернуть управление лаунчеру |

Доступны цветовые константы:

- `COLOR_BLACK` — чёрный.
- `COLOR_DARK_GRAY` — тёмно-серый.
- `COLOR_LIGHT_GRAY` — светло-серый.
- `COLOR_WHITE` — белый.
- `COLOR_TRANSPARENT` — не перерисовывать фон символа.

Разрешение экрана — **320×200 пикселей**. Каждый символ экранного текста занимает 8×8 пикселей, поэтому строка в 40 символов занимает всю ширину экрана. Для старого `gfx_draw_text` сохраняется ASCII-шрифт. `gfx_draw_utf8` дополнительно рисует русские буквы А–Я/а–я, Ё/ё шрифтом 5×7; остальные Unicode-символы пока показываются как `?`.

Особые коды клавиш: `KEY_UP`, `KEY_DOWN`, `KEY_LEFT`, `KEY_RIGHT`. Клавиатурный драйвер использует простую US-подобную раскладку; это не полноценная система раскладок.

**Важно:** не подключай обычную библиотеку C и не рассчитывай на Linux API. Сборка выполняется с `-ffreestanding -nostdlib`, поэтому стандартные функции вроде `printf`, `malloc`, `fopen` и системные вызовы Linux недоступны, пока ты самостоятельно не реализуешь их или не добавишь соответствующую поддержку в SDK/ядро. Не используй глобальную память без необходимости; доступная память приложения ограничена загрузчиком. Приложения выполняются в режиме ядра, поэтому ошибочный указатель или бесконечный цикл без обработки выхода способны повесить всю ОС.

### 3. Минимальное приложение

Создай каталог для исходников. Например, в WSL:

```bash
mkdir -p /mnt/d/MyApps
nano /mnt/d/MyApps/hello.c
```

Вставь следующий код:

```c
#include "customos.h"

int app_main(const customos_api_t *api) {
    while (1) {
        api->gfx_clear(COLOR_BLACK);
        api->gfx_draw_rect(20, 20, 280, 160, COLOR_LIGHT_GRAY);
        api->gfx_draw_text(36, 40, "HELLO FROM CUSTOMOS",
                           COLOR_WHITE, COLOR_TRANSPARENT);
        api->gfx_draw_text(36, 60, "My first external application.",
                           COLOR_LIGHT_GRAY, COLOR_TRANSPARENT);
        api->gfx_draw_text(36, 100, "Press SPACE or ESC to exit.",
                           COLOR_WHITE, COLOR_TRANSPARENT);
        api->gfx_flip();

        while (api->kbd_has_key()) {
            uint8_t key = api->kbd_get_key();
            if (key == ' ' || key == 27) {
                return 0;
            }
        }

        api->timer_sleep(20);
    }
}
```

Приложение рисует экран и остаётся запущенным, пока пользователь не нажмёт Space или Esc. Для выхода важно регулярно проверять клавиатуру, а не застревать в бесконечном цикле, который не обрабатывает ввод.

### 4. Как скомпилировать приложение

Открой терминал Ubuntu/WSL в корне репозитория. В примере исходник лежит по пути `/mnt/d/MyApps/hello.c`, а результат будет записан рядом с ним.

**Шаг A — C в объектный файл `.o`:**

```bash
gcc -m32 -ffreestanding -fno-pie -fno-stack-protector \
    -fno-builtin -nostdlib -Wall -Wextra -O2 -I sdk/ \
    -c /mnt/d/MyApps/hello.c -o /tmp/hello.o
```

На этом шаге GCC проверяет C-код и создаёт 32-битный объектный файл. Если команда завершилась с ошибкой, сначала исправь сообщения компилятора.

**Шаг B — объектный файл в ELF:**

```bash
ld -m elf_i386 -T sdk/app.ld /tmp/hello.o -o /tmp/hello.elf
```

Скрипт `sdk/app.ld` размещает приложение по базовому адресу `0x00400000`, который ожидает текущий загрузчик.

**Шаг C — ELF в исполняемый формат CustomOS CBX:**

```bash
python3 tools/cbxpack.py /tmp/hello.elf \
    /mnt/d/MyApps/hello.cbx \
    --name "Hello" --desc "My first app"
```

Теперь `/mnt/d/MyApps/hello.cbx` — готовый файл приложения CustomOS. Название и описание записываются в заголовок, а затем показываются в лаунчере. Имя приложения должно быть уникальным среди приложений, импортированных в текущий список.

**Кратко, цепочка преобразований такая:**

`hello.c` → GCC → `hello.o` → GNU LD + `sdk/app.ld` → `hello.elf` → `tools/cbxpack.py` → `hello.cbx`.

### 5. Как подключить и запустить внешнее приложение в ОС

В текущей версии приложения загружаются через отдельный пакет AppFS, переданный QEMU при старте. Для первого запуска укажи полученный CBX:

```bash
make run-external EXTERNAL_CBX="/mnt/d/MyApps/hello.cbx"
```

Команда создаёт `build/external_apps.img` из CBX-файла и запускает QEMU с этим пакетом как Multiboot-модулем. Она **не изменяет встроенный список программ ядра** и не требует вручную редактировать Makefile.

После запуска:

1. Нажми **I** в лаунчере, чтобы импортировать приложение из внешнего пакета в управляемую RAM.
2. Найди `Hello` в списке клавишами вверх/вниз и нажми **Enter**.
3. Для выхода из приложения нажми **Space** или **Esc**.
4. Чтобы удалить установленную копию, выдели приложение в лаунчере и нажми **D**. Встроенные приложения удалить нельзя.
5. Нажми **I**, чтобы импортировать удалённое приложение повторно, пока исходный пакет ещё подключён.

Чтобы передать несколько приложений сразу, перечисли CBX-файлы через пробел:

```bash
make run-external EXTERNAL_CBX="/mnt/d/MyApps/hello.cbx /mnt/d/MyApps/another.cbx"
```

Если программа уже скомпилирована на другом компьютере, перенеси готовый файл `.cbx` на этот компьютер (например, в папку на диске D), а затем передай путь к нему в `EXTERNAL_CBX`. Компилятор нужен только для создания CBX из исходного кода; готовый совместимый CBX можно передать напрямую.

Для проверки механизма без собственного исходника используй демонстрационное приложение из репозитория:

```bash
make run-external-demo
```

**Ограничение текущего способа:** файл передаётся в ОС при запуске QEMU. Переключить пакет в уже работающей виртуальной машине нажатием кнопки пока нельзя. Прямое чтение физических USB-флешек и дискет не реализовано; для этого понадобятся драйвер накопителя и файловая система.

### 6. Как включить приложение в стандартную сборку ОС

Если хочешь, чтобы программа присутствовала во встроенном AppFS при каждом обычном запуске `make run`, добавь для неё правила компиляции/упаковки в `Makefile` и включи её `.cbx` в переменную `APPS_CBX`. Затем выполни:

```bash
make clean
make
make run
```

Такое приложение будет встроенным: в текущем лаунчере оно будет защищено от удаления. Для разработки и тестирования обычно удобнее оставлять приложение внешним и использовать `make run-external`.

## Этап 7: игровой движок и игра №3

Мини-движок в `apps/app_game/game_engine.c` и `apps/app_game/game_engine.h` предоставляет модель сущностей, обновление объектов, движение, ограничение границами арены, удаление объектов за пределами поля, прямоугольные столкновения и отрисовку.

**Dodge** — игра на выживание: управляйте светлым квадратом и избегайте падающих блоков. Со временем сложность увеличивается.

- Стрелки или **W/A/S/D** — движение.
- **P** — пауза и продолжение.
- **R** или **Enter** после столкновения — новая попытка.
- **Space** или **Esc** — выход в лаунчер. На стартовом экране **Enter** запускает игру.

## Этап 8: внешние приложения и управление RAM

Встроенные приложения защищены от удаления. Внешние приложения импортируются из AppFS-пакета в отдельное хранилище RAM размером до 12 MiB (фактический размер зависит от объёма памяти, сообщённого загрузчиком). В каталоге одновременно отображается до 64 приложений (ограничение по количеству и доступной памяти). При удалении приложение убирается из каталога, его сохранённая копия стирается, оставшиеся копии уплотняются, а память переиспользуется следующими установками. При запуске исполняемая область и стек очищаются после возврата из приложения. Сохранённые ProjectFS-приложения загружаются в реестр при старте CustomOS.

Внешний AppFS-пакет остаётся источником для повторного импорта до завершения работы ОС. Удаление освобождает установленную копию, но не уничтожает исходный CBX внутри пакета.

## Управление лаунчером

- **Стрелки вверх/вниз** или **W/S** — выбор приложения.
- **Enter** — запуск выбранного приложения.
- **I** — импортировать приложения из внешнего пакета.
- **D** — удалить выбранное внешнее приложение из памяти; встроенные приложения защищены.

## Сборка ядра и запуск

В Ubuntu/WSL из корня репозитория:

```bash
make clean
make
make run
```

Нужны GCC с поддержкой 32-битного кода, NASM, GNU LD, Python 3 и QEMU. Внешние AppFS-пакеты создаются скриптом `tools/mkappfs.py`.


## Редактор визуальных новелл (ветка разработки)

В `feature/visual-novel-editor` разрабатывается приложение **NovelStudio**, использующее API CustomOS, а не Windows/Linux-интерфейс. В этой версии реализованы базовый редактор проектов, сценарный движок, тестовый запуск и упаковка отдельной игры в CBX. Руководство находится в [`docs/VN_EDITOR_GUIDE.md`](docs/VN_EDITOR_GUIDE.md), спецификация языка — в [`docs/VN_LANGUAGE.md`](docs/VN_LANGUAGE.md), архитектурные заметки — в [`docs/VN_EDITOR_ARCHITECTURE.md`](docs/VN_EDITOR_ARCHITECTURE.md).

### Формат сценария

Поддерживаются `label имя:`, реплики с `;`, `menu:`, варианты с завершающим `:`, `endchoice;`, `endmenu;`, `jump имя;` и `return;`. Вложенные меню, условия, переменные, изображения, звук и `call` пока не поддерживаются. Проверка сценария сообщает о синтаксических ошибках, дубликатах меток и несуществующих целях перехода.

### Постоянные проекты и сборки

В CustomOS добавлено хранилище ProjectFS v1 на виртуальном IDE-диске QEMU. Файл образа `customos_data.img` находится в корне рабочего каталога и не удаляется командой `make clean`. Хранилище поддерживает 128 файлов, до 64 КиБ на файл, с CRC-проверкой данных. Исходный сценарий `P_XXXXXXXX.SCR`, метаданные `P_XXXXXXXX.MET` и собранная игра `G_XXXXXXXX.CBX` хранятся отдельно. Успешно собранные игры загружаются в лаунчер при запуске ОС; повторная сборка использует тот же ID проекта.

### Проверки

`make test` собирает диагностические приложения, запускает host-тесты сценарного движка и CBX-упаковщика, а также тесты форматтера образа. CI дополнительно проверяет сохранение контрольного файла после перезапуска QEMU и запускает упакованную тестовую новеллу внутри CustomOS.
