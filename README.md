# CustomOS: экспериментальная 2-битная операционная система

## Назначение

CustomOS — экспериментальная 32-битная x86-операционная система для запуска собственных приложений в формате CBX. В состав входят графическая подсистема 320×200 с четырьмя оттенками, клавиатура PS/2, таймер, API приложений, встроенный каталог AppFS и управление внешними приложениями.

## Архитектура

- **Платформа:** IA-32, Multiboot 1.
- **Сборка ядра:** GCC, NASM и GNU LD.
- **Прерывания:** IDT, PIC 8259, обработчики исключений CPU.
- **Таймер:** PIT на 100 Гц.
- **Графика:** 320×200; внутренний упакованный буфер 2 bpp, вывод через VGA Mode 13h; шрифт 8×8.
- **Приложения:** CBX v1, загружаемые по адресу 0x00400000; API предоставляет текст, графику, ввод и задержки.
- **Встроенные приложения:** AppFS, встраиваемый в ядро при сборке.
- **Внешние приложения:** отдельный AppFS-пакет, передаваемый загрузчиком Multiboot. Приложения копируются в управляемую область RAM при импорте и могут быть удалены из неё.
- **Лаунчер:** графический список приложений с прокруткой, импортом и удалением внешних приложений.

> Важно: приложения работают в одном адресном пространстве и уровне привилегий с ядром. Отдельный стек и очистка памяти после возврата пока не являются аппаратной изоляцией.

## Приложения

1. **AppTest** — проверка загрузчика CBX и вызовов API.
2. **SysInfo** — диагностическая информация о системе.
3. **TextDemo** — демонстрация текстового рендерера, многострочной раскладки и смены контраста клавишей C.
4. **LogicCalc** — тесты арифметики и логики, интерактивный инспектор чисел.
5. **Dodge** — игровое приложение, построенное на мини-движке из `apps/app_game/game_engine.c` и `apps/app_game/game_engine.h`.

### Этап 7: игровой движок и игра №3

Мини-движок предоставляет игровую модель сущностей, обновление объектов, движение, ограничение границами арены, удаление объектов за пределами поля, прямоугольные столкновения и отрисовку.

**Dodge** — игра на выживание: управляйте светлым квадратом и избегайте падающих блоков. Со временем сложность увеличивается.

- Стрелки или **W/A/S/D** — движение.
- **P** — пауза и продолжение.
- **R** или **Enter** после столкновения — новая попытка.
- **Space** или **Esc** — выход в лаунчер. На стартовом экране **Enter** запускает игру.

### Этап 8: внешние приложения и управление RAM

Встроенные приложения защищены от удаления. Внешние приложения импортируются из AppFS-пакета в отдельное хранилище RAM, доступное через лаунчер. При удалении приложение убирается из каталога, его сохранённая копия стирается, а память переиспользуется следующими установками. При запуске исполняемая область и стек очищаются после возврата из приложения.

Внешний AppFS-пакет остаётся источником для повторного импорта до завершения работы ОС. Это похоже на подключённый установочный носитель: **удаление освобождает установленную копию**, но не уничтожает исходный CBX внутри пакета.

**Управление лаунчером:**
- **Стрелки вверх/вниз** или **W/S** — выбор приложения.
- **Enter** — запуск выбранного приложения.
- **I** — импортировать приложения из внешнего пакета.
- **D** — удалить выбранное внешнее приложение из памяти. Встроенные приложения защищены.

## Передача внешнего приложения с основного компьютера

Первый транспорт для внешних программ — файл AppFS, передаваемый QEMU как Multiboot-модуль через `-initrd`. Это позволяет передать файл с Windows/основного компьютера или из WSL, не добавляя к ядру отдельный драйвер дисковода или USB.

Чтобы проверить механизм без собственного приложения, используй готовую демонстрацию:

```bash
make run-external-demo
```

Она компилирует `apps/external_demo/external_demo.c` отдельно от встроенных программ и передаёт полученный CBX через внешний AppFS-модуль. В запущенной ОС нажми **I**, выбери `ExternalDemo` и нажми **Enter**. Вернись в лаунчер, выбери это приложение и нажми **D** — установленная копия будет удалена из управляемой RAM.

Внешнее приложение должно быть скомпилировано в формат CBX для SDK CustomOS. Например, для простого исходника `hello.c`, содержащего `int app_main(const customos_api_t *api)`, выполни из корня репозитория:

```bash
gcc -m32 -ffreestanding -fno-pie -fno-stack-protector \
    -nostdlib -Wall -Wextra -O2 -I sdk/ \
    -c /mnt/d/MyApps/hello.c -o /tmp/hello.o

ld -m elf_i386 -T sdk/app.ld /tmp/hello.o -o /tmp/hello.elf

python3 tools/cbxpack.py /tmp/hello.elf \
    /mnt/d/MyApps/hello.cbx --name "Hello" --desc "External app"
```

Затем передай готовый CBX-файл QEMU:

```bash
make run-external EXTERNAL_CBX="/mnt/d/MyApps/hello.cbx"
```

Для нескольких файлов можно указать пути через пробел:

```bash
make run-external EXTERNAL_CBX="/mnt/d/MyApps/hello.cbx /mnt/d/MyApps/another.cbx"
```

После запуска ОС нажми **I**, выбери появившееся приложение и нажми **Enter**. Для удаления выбери его и нажми **D**. Удалённое приложение можно импортировать снова, поскольку исходный пакет остаётся присоединённым до перезапуска QEMU.

Для обычного запуска без внешнего пакета используется `make run`. Прямой доступ к физическим USB-флешкам и дискетам пока не реализован: для этого отдельно потребуются драйвер накопителя и поддержка файловой системы.

## Сборка и запуск

В Ubuntu/WSL из корня репозитория:

```bash
make clean
make
make run
```

Для сборки нужны GCC с поддержкой 32-битного кода, NASM, GNU LD, Python 3 и QEMU. Внешние пакеты создаются скриптом `tools/mkappfs.py` при вызове `make run-external`.
